# Ciallo-yolo1

YOLO 关键点检测模型导出部署作业

1.作业内容

项目基于 YOLO 模型完成目标检测推理、模型导出与跨格式性能对比实验。将训练得到的权重文件导出为 ONNX 等格式，在相同环境下分别对同一视频进行推理，对比两种模型的推理速度、置信度、检出目标数量，使用IoU（交并比）评估导出前后检测框结果一致性，验证模型导出后的精度损失情况。

最终检验成果：推理速度和检出目标数量在误差范围内，置信度中高，loU极高。

2.本次项目使用的yolo版本：YOLOv8-Pose

3.环境依赖与库：python>=3.8，requirements：

ultralytics  
torch  
onnxruntime  
opencv-python

4\. 导出的模型格式及导出方法：

模型格式：torchscript,onnx.

导出方法：没有新建python文件，直接使用bash命令行：yolo export model=best.pt（原模型） format=onnx（导出后的模型）

5.模型推理的具体运行命令：我在python文件里直接写了模型推理的调用函数，只需在该项目文件下下的bash命令行敲：python infer.py --model best.pt（某格式下的模型） --video test.mp4 （原视频的名称）--output result_pt.mp4（结果视频的名称）即可运行模型并输出视频标注

9.对不同模型格式的理解与实验结论

1).导出过程权重完全不变，只转换计算图存储形式

2).pt 是训练用原生模型；onnx 是为了跨平台部署的通用模型。

又问了问豆包：

```
## 对不同模型格式的理解与实验结论
### 模型格式理解
- `.pt`：PyTorch原生模型格式，同时保存网络结构与权重，支持模型训练与推理，适合模型训练、调优阶段；缺点是绑定PyTorch框架，跨平台部署受限。
- `.onnx`：开放式跨框架通用模型格式，由.pt模型导出得到，**导出过程不会修改权重参数，仅转换计算图存储格式**，脱离PyTorch框架，支持ONNX Runtime、OpenVINO等多种推理引擎。
  支持FP32、FP16两种精度：FP32单精度浮点精度更高，模型文件更大；FP16半精度浮点可减小模型体积、加速推理，会存在轻微精度损失。

### 实验结论
本次使用YOLOv8-Pose关键点检测模型，在CPU环境下对比`.pt`原生模型与导出后的`.onnx`模型，使用同一测试视频完成推理对比实验：
1. 精度层面：两种模型输出检测框平均IoU为0.9935，十分接近1，证明PT转ONNX导出后，模型检测一致性高，精度损失很小。
2. 推理性能：ONNX模型单帧推理耗时更少，推理速度更快。ONNX Runtime引擎对计算图进行优化，更适合工程端部署。
3. 现象说明：ONNX模型检出目标数量相比PT模型存在小幅下降，属于模型格式转换带来的正常现象。
4. 适用场景：`.pt`格式适合模型训练、迭代调参；`.onnx`格式更适合跨平台部署，以极小的精度代价换取更快的推理速度。
```

10.小巧思：尝试了一下FP16的文件，做了如下数据对比表格：（CPU）跑

| 模型             | 精度        | 文件大小     | 单帧推理耗时   | 平均置信度  | FPS   | 总检出目标数 |
| -------------- | --------- | -------- | -------- | ------ | ----- | ------ |
| best_fp16.onnx | FP16（半精度） | 5,046 KB | 0.1357 s | 0.6518 | 7.37  | 468    |
| best_fp32.onnx | FP32（全精度） | 9,958 KB | 0.0350 s | 0.6523 | 28.57 | 468    |

1. FP16半精度模型文件大小约为 FP32 的一半，存储占用更小。
2. FP16推理速度反而更慢。（豆包解释原因）：ONNX Runtime 在运行 FP16 模型时，需要额外把 FP16 数据转换成 FP32 再计算，带来额外转换开销，因此单帧耗时大幅增加，FPS 明显下降。
3. 两组模型的平均置信度、检出目标总数几乎完全一致，半精度量化几乎没有造成检测精度损失。
